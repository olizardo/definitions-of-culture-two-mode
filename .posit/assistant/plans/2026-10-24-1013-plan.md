# Plan: rebuild both two-mode networks as current igraph objects

Date: 2026-10-24. Scope: `data/kkcc_two_mode.rds` (56 notions × 135 definitions) and
`data/kkcc_two_mode_main.rds` (16 main categories × 135 definitions). Locked igraph is 2.3.3 (renv.lock).

## Why rebuild

1. The fine-grained file stores its graph in an old igraph serialization. `igraph` 2.3.3 rejects it
   ("Must provide a graph object"), so its vertex attributes (`is_main`, `parent_category`, `def_group`,
   `def_type`) cannot be read or verified.
2. The construction code for the fine graph's concept attributes (`is_main`, `parent_category`) is not in
   any commit. It was run interactively. The concept-to-category mapping therefore has no script behind it.
3. `scripts/analysis-collapse-main.R` uses `def_attrs` without defining it. It works only in a session that
   already has that object loaded.
4. Three scripts (`build-definition-years.R`, `build-supplement-bibliography.R`, and the collapse step)
   patch the rds files in place. The result depends on run order. The notes say a rebuild drops attributes.
5. The two files store definition attributes in different forms: a data frame in the fine file, a named
   list in the main file. Downstream scripts read `def_attrs$type` and similar.

## What is already known to be correct (keep as the reference)

- Concept × definition biadjacency, fine: 56 × 135, 316 ties, binary, rownames = the 56 notions. Stored in
  `kkcc_two_mode.rds$biadjacency`. Can be read without igraph. This is the source of the ties.
- Main biadjacency: 16 × 135, 301 ties. `data/kkcc_biadjacency_main.csv` matches it.
- Definition attributes (author, year, year_orig, year_suffix, decade, bib_entry, author_canonical, bib_ref,
  bib_year, match_status, group, subgroup code, type) agree with `data/kkcc-definition-years.csv` and
  `data/kkcc-definition-biblio.csv` for all 135 codes. D3-1 has no year by design. F4-6 is inferred (Kluckhohn
  & Kelly 1945a).
- Category totals in `analysis-collapse-main.R` (`uses.printed`) give the 16 main categories and their
  printed use counts.

## Steps

0. **Back up** the current rds files to `$PA_SCRATCH_DIR` (not the repo) before any change.

1. **Recover the concept metadata from Table 2, not from list position.** The 56 labels include auxiliaries
   that appear before their parent (for example `Habit` before `HABITS`, `Belief` before `BELIEFS`, `Custom`
   before `CUSTOMS`, `Adjustment` before `ADJUSTMENTS`). Position alone is not reliable. Read the parent of
   each auxiliary from the printed Table 2 layout (`documents/ROBAFC-5.1.pdf` text, and the page image if
   needed). Check that the parent mapping reproduces the printed totals in `uses.printed`. Record the mapping
   as a CSV in `data/` (for example `data/kkcc-concept-categories.csv`: `concept`, `is_main`,
   `parent_category`, `uses_printed`), with its evidence.

2. **Write one builder**, `scripts/build-two-mode-networks.R`, run from the project root in a fresh session.
   It reads only files:
   - the fine biadjacency (from the existing rds, or from a CSV exported first),
   - the concept-category CSV from step 1,
   - `kkcc-definition-years.csv` and `kkcc-definition-biblio.csv` for definition attributes.

   It builds two `igraph` objects with `graph_from_biadjacency_matrix()`, then sets attributes by name.
   Vertex order must be checked against names, not assumed (the notes warn about this).

3. **Node attribute schema** (proposed):

   Concepts (`type = FALSE`):
   - `name`, `node_type = "concept"`, `is_main` (logical), `parent_category` (main category name, for all
     concepts), `n_uses` (row sum of the binary matrix).
   - In the fine network only: `main_category` (the parent) is the category used for colouring.

   Definitions (`type = TRUE`):
   - `name` (code), `node_type = "definition"`, `def_group` (A–G), `def_subgroup` (e.g. C1), `def_type`
     (descriptive, historical, normative, psychological, structural, genetic, incomplete),
   - `author`, `author_canonical`, `year`, `year_orig`, `year_suffix`, `decade`, `bib_entry`, `bib_year`,
     `bib_ref`, `match_status`.
   - Verbatim definition texts are NOT embedded. They are rights-restricted (see AGENTS.md and README).
     They stay in the CSVs.

   Graph attributes: `name`, `built` (date), `source_files`, `igraph_version`, `notes` (fine and main).

   Keep `type` as the bipartite flag. Do not keep the separate `def_attrs` data frame in the rds; the
   attributes live on the vertices. (Question for the user; see below.)

4. **Validation** (a script, `scripts/check-two-mode-networks.R`, run after the build):
   - Both files load with `readRDS()` and `igraph` functions work (`vcount`, `ecount`, `is_bipartite`,
     `is_connected`).
   - Fine: 56 + 135 vertices, 316 edges. Main: 16 + 135 vertices, 301 edges. Adjacency equals the
     biadjacency matrix exactly. The main matrix equals the collapse of the fine matrix by category.
   - Every definition attribute equals the CSV value for its code (author, year, decade, bib fields,
     match_status, group, subgroup, type). Every concept has a parent in the 16 categories.
   - Printed category totals are ≥ binary totals (as the collapse script checks).
   - Regression: the existing analysis outputs (`data/kkcc-ca-*.csv`, `data/kkcc-centrality-main.csv`,
     `data/kkcc-prestige-*.csv`, `data/kkcc-score-means-*.csv`) must be unchanged after rerunning the
     analysis scripts against the new files. Any difference must be explained before it is accepted.

5. **Update consumers.** Scripts that read `def_attrs` (`analysis-backbone-main.R`, `analysis-ca-mst-main.R`,
   `analysis-centrality-prestige-main.R`, `analysis-index-b.R`, `build-definition-texts.R`) and the report
   `kkcc-two-mode.qmd` move to vertex attributes (or the CSVs). Update the data dictionary in `README.md`,
   `docs/PROVENANCE.md` (the construction note), and the project memory in `AGENTS.md`.

6. **Retire the patch-in-place steps** only after step 4 passes. Either fold the attribute steps into the new
   builder, or keep `build-definition-years.R` and `build-supplement-bibliography.R` as inputs to it. Do not
   leave two code paths that write the same rds.

7. **Render check.** Render `kkcc-two-mode.qmd` in a fresh session and confirm it runs without any object
   from an earlier session.

## Decisions needed from the user

1. Keep the file names `kkcc_two_mode.rds` and `kkcc_two_mode_main.rds` (recommended), or use new names?
2. Replace the `def_attrs` data frame with vertex attributes, updating the downstream scripts (recommended),
   or keep `def_attrs` as well?
3. Merge the attribute scripts into one builder (recommended), or keep three scripts that run in order?
4. Confirm that the concept-to-category mapping is to be re-derived from the printed Table 2 (step 1), with
   the printed totals as the check.
5. Confirm that verbatim definition texts stay out of the rds files.

## Risks

- The concept mapping is the one piece with no existing script. Step 1 is the only step that needs a page
  check, and any uncertain auxiliary should be listed as an open item rather than guessed.
- Analysis outputs may change if the vertex order or the parent mapping changes. The regression check in
  step 4 is the guard.
